# UPF × NOVA stance

Combines two earlier projects:

- `~/Documents/upf_bibliography` supplies the corpus, metadata and citation edges (OpenAlex).
- `~/Desktop/UPF citation network` supplied the idea: classify each paper's stance towards NOVA
  and its engagement with critiques. Here it is applied to the real citation network.

## Setup
```bash
git clone https://github.com/ggkuhnle/upf_nova_stance && cd upf_nova_stance
python -m venv venv && source venv/bin/activate && pip install -r requirements.txt
```
Set your e-mail (used for the polite OpenAlex/Unpaywall pools) in a git-ignored `config.local.json`:
`{"mailto": "you@your.institution"}`. The corpus comes from [upf_bibliography](https://github.com/ggkuhnle/upf_bibliography):
build it first and point `bibliography_data_dir` in `config.json` at its `data/<prefix>` folder.
`data/` and `output/` are not in the repository; the explorer is regenerated by `pipeline/build_network.py`.
For local LLM classification install [Ollama](https://ollama.com) and `ollama pull llama3.1:8b`.

## Run
```bash
# 1. make sure upf_bibliography/data/upf exists (python make_dashboard.py --fetch there)
~/Documents/upf_bibliography/venv/bin/python run_all.py          # rule-based
~/Documents/upf_bibliography/venv/bin/python run_all.py --backend llm   # needs `pip install anthropic`, ANTHROPIC_API_KEY
```
Steps: `fetch_abstracts.py` → `classify_stance.py` → `build_network.py`. Settings in `config.json`
(set `pdf_dir` to use full text, files named `<doi with / → _>.pdf`; needs pdfplumber).

## Output (`output/`)
`stance_network_cytoscape.html` (Cytoscape.js explorer, as in upf_bibliography), `stance_by_year.html`,
`stance_citation_matrix.csv` (who cites whom), `summary.md`. Per-paper labels: `data/stance.csv`.

## Changes from the Desktop version
- OpenAlex instead of PubMed, so real citation edges exist.
- Only sentences mentioning NOVA are scored (plus the next sentence), not the whole text.
- Optional LLM backend; PDFs optional rather than required (no hard-coded `D:\` path).

## Caveats
Abstract-only rule-based labels are noisy (first run: 48 critical, 19 mixed, 174 supportive,
1081 neutral_use out of 6942). Cues such as "debate" or "heterogeneity" yield false "critical"
labels. Use `--backend llm` or PDFs, and spot-check `data/stance.csv`, before drawing conclusions.
